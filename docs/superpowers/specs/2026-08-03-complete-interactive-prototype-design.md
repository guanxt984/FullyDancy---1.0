# FullyDancy 完整可交互原型设计

## 目标

将当前功能骨架重构为一套可从首页连续体验到舞蹈挑战的 Web 原型，并沿用任务 `019f79da-9046-7620-a578-4d01bc084974` 已确认的视觉语言。

原型服务于产品流程验证，不追求复杂算法或生产级精度。视频播放、摄像头和姿态关键点使用真实浏览器能力；节拍提取、身体校准和动作判定采用可解释的最小实现。所有视频、音频、摄像头画面、姿态点和身体数据均在浏览器本地处理。

## 用户流程

正式流程固定为：

`首页 → 关卡选择 → 卡点分析与设置 → 身体校准 → 舞蹈挑战`

本轮不在首页暴露摄像头性能指标、模型档位或调试按钮。技术验证能力保留在代码中，但退出正式用户流程。

## 页面与交互

### 1. 首页

- 使用内置舞蹈视频作为静音、循环的动态舞台背景。
- 深色遮罩确保远距离阅读时文字仍清晰。
- 显示品牌 `fullydancy`、一句产品说明和唯一主操作 `开始游戏`。
- 点击后进入关卡选择，不申请摄像头权限。

### 2. 关卡选择

- 显示 `选择你的挑战`。
- 可用关卡为 `8月3日舞蹈挑战`，使用内置视频的真实预览。
- 同屏展示 `上传自己的舞蹈`，但必须处于禁用状态并标记 `即将开放`。
- 禁用入口不能打开文件选择器，不能接受拖放，也不能调用上传逻辑。
- 选择内置关卡后进入卡点分析页面。

此处展示上传入口是产品路线提示，不代表恢复 MVP 上传功能；项目仍无上传接口、对象 URL、后端或文件处理流程。

### 3. 卡点分析与设置

- 显示可播放、暂停和拖动的内置舞蹈视频。
- 用户点击 `分析卡点` 后，从视频音轨生成少量候选卡点。
- 候选卡点不能来自关卡内预设表；使用浏览器本地的轻量音频能量峰值分析即可，不要求严格 BPM 识别。
- 每个候选点只提供四种状态：删除、只卡节奏、打开、蹲低。
- 同一卡点最多拥有一个动作；切换动作会覆盖前一个动作。
- `打开` 的最终含义为：卡点时刻任意一只手臂伸直即命中，主要依据大臂与小臂夹角。
- 用户点击 `确认卡点` 后进入身体校准。
- 分析失败统一显示 `关卡加载失败，请重试`，并保留视频与重试入口。

### 4. 身体校准

- 只有进入此页时才申请摄像头权限。
- 摄像头全屏铺满舞台，实时叠加骨架。
- 按顺序引导：`自然站立 → 双臂打开 → 约 90°下蹲`。
- 用户不填写身体数值，也不点击“完成当前姿势”。系统检测到全身入镜后自动采集并推进。
- 原型使用约 1 秒的短采样窗口并保存最少数据：肩宽、身体画面比例、左右有效臂长、站立髋部高度和下蹲参考。
- 数据只保存在当前内存会话中。
- 校准完成后显示短倒计时并自动进入舞蹈挑战。

### 5. 舞蹈挑战

- 同时显示内置示范视频与用户镜像摄像头，采用清晰的双舞台布局；宽屏左右并列，窄屏上下排列。
- 示例视频保留声音和原始控制能力；挑战开始时从开头播放。
- 卡点临近时显示短促提示，命中时使用荧光黄绿色闪光。
- `打开`：以卡点窗口中任意一只手臂的肩—肘—腕夹角达到简单阈值为准；提前伸直并保持到卡点仍算命中。
- `蹲低`：使用左右膝关节夹角的简单阈值。
- `只卡节奏`：本轮只显示拍点提示，不要求复杂速度模型。
- 本轮只需把挑战运行起来并显示单个卡点的即时命中/未命中反馈；正式计分、Combo 和战绩页留到后续阶段。

## 视觉系统

视觉直接继承参考任务的沉浸式舞台语言，而不是普通网站或卡片式 SaaS 页面。

- 背景：接近纯黑的冷黑舞台。
- 主文字：接近白色。
- 唯一主强调色：荧光黄绿色，用于主按钮、当前步骤、命中反馈和骨架。
- 次要提示：半透明浅灰；错误使用克制的暖黄色，不使用大面积红色。
- 媒体是主视觉，装饰元素从简。
- 品牌位于左上，当前步骤或状态位于右上，主操作位于底部中央，隐私说明位于底部边缘。
- 主按钮使用大尺寸圆角胶囊；面板最大圆角为 16px，避免过度圆角卡片。
- 只在状态切换和命中时使用 150–250ms 短动效，并支持 `prefers-reduced-motion`。
- 字体使用系统无衬线字体；站远后需要阅读的指引使用大字号和短句。
- 颜色在 CSS 中使用 OKLCH 变量，同时保持与参考页面肉眼一致。
- 移动端保留安全区，按钮触控区域不小于 44px。

## 轻量架构

使用一个 React 会话状态管理正式流程：

```ts
type PrototypeScreen =
  | "home"
  | "level-select"
  | "analysis"
  | "calibration"
  | "countdown"
  | "challenge";
```

- 不引入路由、全局状态库、后端、数据库或账号系统。
- 页面组件只接收当前会话数据和下一步回调。
- 内置视频元数据继续由 `BUILT_IN_LEVEL` 提供。
- 节拍候选、用户标记和校准档案只存放在当前 React 会话内存中。
- 复用已有 MediaPipe provider、摄像头启动与骨架绘制代码；不复制第二套识别器。

建议组件边界：

- `HomeScreen`：产品介绍与开始操作。
- `LevelSelectScreen`：可用内置关卡与禁用上传入口。
- `AnalysisScreen`：视频、轻量分析、卡点编辑和确认。
- `CalibrationScreen`：摄像头、骨架、自动三步采样。
- `ChallengeScreen`：示范视频、用户镜头和即时卡点反馈。
- `App`：仅管理线性流程和内存会话数据。

## 错误与资源清理

- 摄像头拒绝授权、无设备和模型启动失败时，在当前舞台显示简短说明与重试按钮。
- 离开校准或挑战页面时停止摄像头轨道、姿态循环和模型资源。
- 音频分析失败不清除用户已经完成的页面选择。
- 页面刷新允许回到首页；本轮不做流程持久化。

## 测试与验收

行为测试只覆盖用户可见的关键路径：

- 首页点击后进入关卡选择。
- 上传入口可见但不可操作，且不存在文件输入。
- 只能选择唯一内置关卡。
- 分析生成的候选点可改为 `打开 / 蹲低 / 只卡节奏`，一个卡点只有一个动作。
- 确认卡点后才申请摄像头并进入自动校准。
- 三步校准完成后进入倒计时与挑战。
- 离开媒体页面时正确释放摄像头与识别资源。
- 桌面和移动宽度下主操作可见，焦点状态清晰。

每完成一个用户可检验的小阶段，就启动本地页面并暂停：

1. 首页与关卡选择。
2. 卡点分析与设置。
3. 身体校准与挑战入口。

## 本轮明确不做

- 真正的用户视频上传。
- 通用多关卡框架。
- 后端、账号、云端存储和排行榜。
- 严格 BPM、舞蹈动作识别模型或复杂时间序列算法。
- 正式分数、Combo、战绩卡和跨会话保存。
- 手势控制倍速、录屏或切歌。
