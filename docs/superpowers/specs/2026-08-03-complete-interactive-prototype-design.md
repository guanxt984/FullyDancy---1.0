# FullyDancy 完整可交互原型设计

**状态：** 已更新至当前浏览器原型  
**最近更新：** 2026-08-17

## 目标

将 FullyDancy 当前功能串联成一套可从首页连续体验到舞蹈挑战页的 Web 原型。原型服务于产品流程验证与作品集展示，不追求复杂算法或生产级评分精度。

本原型坚持本地优先：视频、音频、摄像头画面、姿态点、示范骨架缓存和身体校准数据均在浏览器本地处理，不上传服务器。

## 用户流程

正式流程固定为：

`首页 → 关卡选择 → 卡点分析与设置 → 身体校准 → 舞蹈挑战`

本轮不在首页暴露摄像头性能指标、模型档位或调试按钮。技术验证能力保留在代码中，但退出正式用户流程。

## 页面与交互

### 1. 首页

- 使用 Canvas 2D 绘制荧光粒子舞者动效，替代早期视频背景。
- 粒子自由漂浮，并周期性凝聚成抽象舞者轮廓，表达“肢体舒展”和“节奏凝聚”的产品气质。
- 深色遮罩确保远距离阅读时文字仍清晰。
- 显示品牌 `FullyDancy`、一句产品说明和唯一主操作 `开始游戏`。
- 点击后进入关卡选择，不申请摄像头权限。
- 支持 `prefers-reduced-motion`：减少动态用户看到更克制的粒子状态。

### 2. 关卡选择

- 显示 `选择你的挑战`。
- 可用关卡为 `8月3日舞蹈挑战`，使用内置视频资源。
- 同屏展示 `上传自己的舞蹈（即将开放）`，但必须处于禁用状态。
- 禁用入口不能打开文件选择器，不能接受拖放，也不能调用上传逻辑。
- 选择内置关卡后进入卡点分析页面。

此处展示上传入口是产品路线提示，不代表恢复 MVP 上传功能；项目仍无上传接口、对象 URL、后端或文件处理流程。

### 3. 卡点分析与设置

- 页面以示范视频为主视觉，视频高度尽量接近可用页面高度。
- 视频下方只有一条时间轴，不出现第二条进度条。
- 时间轴上有两类点：
  - 荧光大点：分析生成的候选卡点，可点击。
  - 白色小点：当前视频播放进度，会随 `timeupdate` 移动。
- 点击时间轴任意位置会跳转视频播放位置。
- 点击卡点或选中卡点下方操作，也会跳转到该卡点时刻。
- 用户点击 `分析卡点` 后，从视频音轨生成少量候选卡点。
- 候选卡点不能来自关卡内预设表；使用浏览器本地的轻量音频能量峰值分析即可，不要求严格 BPM 识别。
- 每个候选点只提供四种状态：删除、卡节奏、手臂打开、下蹲。
- 同一卡点最多拥有一个动作；切换动作会覆盖前一个动作。
- 只显示当前选中卡点的操作，避免操作项把视频区挤没。
- 每个卡点在时间轴上显示一个小 icon；若当前卡点有对应动作，则显示对应符号。
- `手臂打开` 的最终含义为：卡点时刻任意一只手臂伸直即命中，主要依据肩—肘—腕夹角。
- 分析页会对示范视频做全程骨架缓存，并在当前时刻或选中卡点附近叠加示范骨架。
- 当卡点为 `手臂打开` 或 `下蹲` 时，骨架高亮关键部位。
- 用户点击 `确认卡点` 后进入身体校准。
- 分析失败统一显示 `关卡加载失败，请重试`，并保留视频与重试入口。

### 4. 身体校准

- 只有进入此页时才申请摄像头权限。
- 显示本地摄像头画面，并实时叠加用户骨架。
- 按顺序引导：
  1. 全身入镜。
  2. 站直记录。
  3. 四肢展开。
- 用户不填写身体数值，也不需要手动输入身高、臂长或角度。
- 系统采集最小校准档案：肩宽、髋宽、身体高度、臂展、镜头尺度和采集时间。
- 数据只保存在当前内存会话中。
- 校准完成后进入舞蹈挑战页。

### 5. 舞蹈挑战

- 当前阶段是极简挑战页壳子，用于闭合完整交互流程。
- 页面显示内置示范视频、摄像头舞台占位和已载入卡点数量。
- 示例视频保留原生播放控制，方便用户验证流程。
- 摄像头舞台暂时显示“下一步接入实时摄像头、骨架和命中反馈”的占位说明。
- 该页不做正式判定、评分、Combo 或结果页。

后续挑战页将补充：

- 同步播放示范视频与用户镜像摄像头。
- 使用已确认卡点进行节奏命中判定。
- 对 `手臂打开` 和 `下蹲` 卡点进行动作状态判定。
- 命中时显示荧光闪光、粒子、`FULL OUT` 或 `DROP LOW`。

## 视觉系统

视觉直接继承沉浸式舞台语言，而不是普通网站或卡片式 SaaS 页面。

- 背景：接近纯黑的冷黑舞台。
- 主文字：接近白色。
- 唯一主强调色：荧光黄绿色，用于主按钮、当前步骤、卡点、命中反馈、骨架和粒子。
- 次要提示：半透明浅灰；错误使用克制的暖黄色，不使用大面积红色。
- 首页粒子动效是品牌气质表达，但不能喧宾夺主；标题和开始按钮永远保持最高可读性。
- 媒体是分析页主视觉，卡点操作必须为视频让位。
- 品牌位于左上或视觉中轴附近，当前步骤或状态位于右上，主操作贴近底部或当前任务区域。
- 主按钮使用大尺寸圆角胶囊；面板最大圆角约 16px，避免过度圆角卡片。
- 只在状态切换、卡点选中、骨架高亮和命中反馈时使用短动效。
- 字体使用系统无衬线字体；站远后需要阅读的指引使用大字号和短句。
- 颜色在 CSS 中使用 OKLCH 变量，保持黑色舞台和荧光主色一致。
- 移动端保留安全区，按钮触控区域不小于 44px。

## 轻量架构

使用一个 React 会话状态管理正式流程：

```ts
type PrototypeScreen =
  | "home"
  | "level-select"
  | "analysis"
  | "calibration"
  | "countdown"
  | "challenge";
```

- 不引入路由、全局状态库、后端、数据库或账号系统。
- 页面组件只接收当前会话数据和下一步回调。
- 内置视频元数据由 `BUILT_IN_LEVEL` 提供。
- 节拍候选、用户标记、示范骨架缓存和校准档案只存放在当前 React 会话内存中。
- 复用已有 MediaPipe provider、摄像头启动与骨架绘制代码；不复制第二套识别器。
- Canvas 2D 用于首页粒子、骨架叠加和未来命中特效，不引入大型游戏引擎。

组件边界：

- `HomeScreen`：产品介绍与开始操作。
- `ParticleDancerHero`：首页荧光粒子舞者动效。
- `LevelSelectScreen`：可用内置关卡与禁用上传入口。
- `AnalysisScreen`：视频、轻量分析、单时间轴、卡点编辑、示范骨架叠加和确认。
- `CalibrationScreen`：摄像头、骨架、自动三步采样。
- `ChallengeScreen`：示范视频、摄像头舞台占位和已载入卡点。
- `App`：仅管理线性流程和内存会话数据。

## 错误与资源清理

- 摄像头拒绝授权、无设备和模型启动失败时，在当前舞台显示简短说明与重试按钮。
- 离开校准或挑战页面时停止摄像头轨道、姿态循环和模型资源。
- 音频分析失败不清除用户已经完成的页面选择。
- 页面刷新允许回到首页；本轮不做流程持久化。
- reduced-motion 用户不执行高频粒子动画。

## 测试与验收

行为测试只覆盖用户可见的关键路径：

- 首页点击后进入关卡选择。
- 首页存在荧光粒子舞者 Canvas，且 reduced-motion 有降级标记。
- 上传入口可见但不可操作，且不存在文件输入。
- 只能选择唯一内置关卡。
- 分析生成的候选点可改为 `手臂打开 / 下蹲 / 卡节奏`，一个卡点只有一个动作。
- 时间轴点击、卡点点击和卡点操作都能联动视频时间。
- 确认卡点后才申请摄像头并进入自动校准。
- 三步校准完成后进入挑战页壳子。
- 桌面和移动宽度下主操作可见，焦点状态清晰。

每完成一个用户可检验的小阶段，就启动本地页面并暂停：

1. 首页与关卡选择。
2. 卡点分析与设置。
3. 身体校准与挑战入口。
4. 首页粒子品牌动效。

## 本轮明确不做

- 真正的用户视频上传。
- 通用多关卡框架。
- 后端、账号、云端存储和排行榜。
- 严格 BPM、舞蹈动作识别模型或复杂时间序列算法。
- 正式分数、Combo、战绩卡和跨会话保存。
- 手势控制倍速、录屏或切歌。
