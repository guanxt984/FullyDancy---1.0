# fullydancy MVP 产品设计

## 产品定义

fullydancy 是一个 Web 端个人舞蹈音游，帮助已经具备初步练舞能力、能够自行学会一段舞的用户在家练习动作卡点和肢体舒展。

用户上传一段卡点鲜明的本地舞蹈视频，系统自动识别音乐强拍，用户为少量拍点添加“打开”或“蹲低”要求。挑战前，系统通过摄像头自动录入用户当局的身体比例、四肢数据和动作基准；挑战时分别评价节奏落点与动作状态，通过短促、有冲击力的反馈，引导用户把动作跳得更准、更舒展、更有劲。

产品不限定舞种，但更适合音乐卡点明确、动作幅度清晰的视频。

## 目标用户

首版面向有少量翻跳经验、能够自行学会一段舞的爱好者。他们习惯独自对着视频练习，希望改善动作缩水、手臂没有伸直、下蹲不足和卡点不利落的问题，同时获得接近音游或舞蹈机的爽感。

fullydancy 不负责教会一段舞，也不评判用户是否还原了原视频。它评价的是用户自己设置的动作意图是否在音乐强拍上完成。

## 产品原则

- 节奏是玩法主干，动作状态判定只出现在少量拍点。
- 奖励正确动作的强度高于批评错误动作的强度。
- 实时提示必须短促，不用长篇纠错打断舞蹈。
- 挑战前自动采集身体数据，不要求用户手动填写身高、四肢长度或角度。
- 使用相对身体比例和关节角度，不使用屏幕绝对坐标判断动作。
- 系统只判断它能够可靠判断的内容。
- 摄像头看不清时不把技术失败算作用户错误。
- 产品只定义体验和规则，不设置成功门槛、观察指标、用户任务或数据目标。
- 首版保持本地优先、无需登录、无需后端，视频和摄像头画面不上传。

## 核心流程

1. 用户上传 15–60 秒的本地舞蹈视频。
2. 系统在浏览器中分析音轨并标出较突出的强拍。
3. 用户试听和预览强拍，保留纯节奏点，或给少量拍点添加“打开”或“蹲低”要求。
4. 系统通过动画、语音和倒计时引导用户完成自动身体与机位校准。
5. 用户开始挑战，系统同步播放视频、音乐并读取摄像头姿态。
6. 系统分别判断节奏落点和可选动作状态，实时反馈 Combo、能量和命中效果。
7. 挑战结束后展示战绩卡。
8. 用户点击“再来一局”时先完成约 2 秒的机位复核；机位基本一致则直接重试，明显变化时才重新完整校准。

## 关卡生成与编辑

### 自动生成的职责

系统只自动识别音乐强拍，不自动识别原视频中的动作、姿势、运动变化点或动作语义。

系统应优先保留较突出的强拍，避免把每一拍都变成判定点。自动结果是一个可快速确认的初始谱面，而不是完整编舞分析。

### 卡点结构

每个被保留的强拍都默认进行“快速到位”判定。“打开”和“蹲低”是附加在强拍上的动作状态要求，不是与节奏平行的另一套时间点。

```text
强拍卡点
├─ 基础判定：快速到位
└─ 可选动作状态
   ├─ 打开：任意一只手臂伸直
   └─ 蹲低：髋部达到个人下蹲深度
```

用户可以对每个强拍执行四种操作：

- 只卡节奏：仅判断快速到位。
- 打开：判断快速到位，并检查卡点窗口内是否有任意一只手臂伸直。
- 蹲低：判断快速到位，并检查卡点窗口内重心是否达到个人下蹲深度。
- 删除：不在这个强拍进行判定。

首版同一个强拍最多添加一个动作要求，避免同一时刻出现多项动作错误。

用户选择“打开”或“蹲低”，表达的是“我希望自己在这个强拍满足该动作状态”，并不表示系统识别出了原视频中的动作。关卡确认界面必须明确说明这一点。

### 卡点数据模型

每个卡点至少包含：

- `timeSec`：目标强拍的媒体时间。
- `beatIndex`：强拍序号。
- `action`：`rhythm`、`open` 或 `squat`。
- `enabled`：是否保留该卡点。
- `timingWindowsMs`：各节奏评价的时间窗口。

卡点不保存原舞姿势、屏幕坐标、左右手臂方向或需要用户编辑的身体角度。

## 自动身体与摄像头校准

校准用于建立用户当局的身体尺度和动作基准，并确认摄像头具备判定条件。用户不填写数据，也不需要在远处操作按钮；系统通过引导动作和稳定帧自动完成采集。

### 首次挑战的完整校准

1. **全身入镜**：检查头、肩、髋、膝和踝是否可见，并提示用户前进、后退或调整机位。
2. **自然站直**：记录身体画面尺度、中心位置、肩宽、髋宽、躯干长度、左右大臂、前臂、大腿、小腿的相对长度，以及站立髋部高度。
3. **双臂伸直**：用户可朝任意舒适方向伸直双臂，不要求 X 形；系统记录左右手臂的个人伸直角度，并确认肩、肘、腕能够可靠识别。
4. **挑战下蹲**：仅当当前谱面包含“蹲低”卡点时出现，记录用户主动完成的挑战下蹲深度。

系统从连续稳定帧中取中位值，不依赖单帧结果。完整校准目标时长为 6–8 秒。

### 校准记录

当局校准至少包含：

- 身体画面尺度和中心位置。
- 肩宽、髋宽和躯干长度。
- 左右大臂、前臂、大腿和小腿的相对长度。
- 左右手臂的个人伸直角度。
- 站立时的髋部高度。
- 用户主动完成的挑战下蹲深度。
- 所需关键点的可见度和置信度。
- 用于重试复核的机位签名。

身体和四肢数据用于消除身高、体型以及距摄像头远近造成的误差，不用于复原或评价原舞姿势。

### 再来一局的快速复核

用户自然站立即可。系统用约 2 秒比较全身可见度、身体画面尺度、中心位置、四肢比例和机位签名：

- 机位基本一致时，复用当前挑战会话的完整校准并直接进入倒计时。
- 距离、角度或入镜范围明显变化时，重新进行完整校准。

## 双层判定模型

每个有效强拍的节奏与动作状态分别判定：

- **节奏判定**决定 `Perfect`、`Great`、`Early`、`Late`、`Miss` 和 Combo。
- **动作状态判定**决定 `FULL OUT`、`DROP LOW`、动作完成率、额外分数和能量。

用户即使保持手臂伸直或保持蹲低，也只能满足动作状态；只有身体整体在强拍附近形成动作落点，才会获得节奏命中。

### 快速到位

产品不比较用户与原视频的姿势。快速到位被定义为：用户身体的整体运动在强拍附近明显收束，形成清晰的动作落点。

系统观察经身体尺度归一化后的运动特征：

- 强拍前存在明显运动。
- 强拍附近整体速度快速下降，出现局部极小值，或运动方向发生明显切换。
- 系统将检测到的动作落点与音乐强拍比较时间差。
- 一个动作落点只能匹配一个强拍，避免重复计分。

首版默认时间窗口：

- `Perfect`：±100ms。
- `Great`：±200ms。
- `Early` 或 `Late`：±350ms。
- `Miss`：超过 ±350ms，或没有检测到明确落点。

阈值集中配置。上传视频的媒体时间是唯一游戏时钟；摄像头帧在送入姿态模型前记录对应媒体时间，模型推理耗时不改变该帧的判定时间。

### 打开

系统分别计算左右肩—肘—腕的夹角：

- 卡点窗口内，任意一只可靠识别的手臂达到个人伸直阈值，即满足“打开”。
- 手臂可以向上、向侧面、向前或斜向伸直，方向不参与评分。
- 不判断手腕离身体的距离，不比较双臂宽度，也不比较原视频姿势。
- 不要求手臂在卡点附近从弯曲变为伸直；提前伸直并保持也可以满足动作状态。
- 另一只手臂可以弯曲、遮挡或执行其他舞蹈动作。
- 一侧不可识别时使用另一侧；两侧都不可识别时，本次动作不可判定，不算失败。

个人伸直阈值由校准角度减去小幅容差得到，并通过集中配置调整。

实时反馈：

- 命中：`FULL OUT`。
- 未命中：`手臂伸直`。

### 蹲低

系统比较站立髋部高度与挑战时髋部高度，计算下降幅度相对于校准挑战下蹲深度的比例。

- 卡点窗口内达到校准下降幅度的约 85% 即满足“蹲低”。
- 允许提前蹲低并保持。
- 该判定只评价重心下降，不评价膝盖方向、背部姿态或专业深蹲技术。
- 髋部或其他所需关键点不可识别时，本次动作不可判定，不算失败。

实时反馈：

- 命中：`DROP LOW`。
- 未命中：`再低一点`。

### 识别失败

手臂、髋部或其他所需关键点被遮挡、离开画面或置信度不足时：

- 不把本次动作判为失败。
- 不计入动作完成率的分母。
- 给出“保持全身入镜”等机位提示。
- 不因动作识别失败打断节奏 Combo。

## 计分与 Combo

总分由两部分组成：

- 节奏准确率：70%。
- 动作完成率：30%。

具体分值映射应集中配置，避免散落在界面或判定代码中。

Combo 只由节奏判定维持。打开或蹲低命中时提供额外分数、能量和视觉奖励；动作未命中时不给动作奖励，但不打断 Combo。

这种设计使节奏始终是玩法主干，也降低摄像头偶发误判对核心爽感的破坏。

## 实时反馈

挑战界面的主要反馈包括：

- `Perfect`、`Great`、`Early`、`Late`、`Miss`。
- `FULL OUT` 和 `DROP LOW`。
- Combo。
- 能量或 Fever 表现。
- 强命中时的震动感、粒子、光效和短音效。

同一个强拍只显示一个主反馈：

1. 节奏与动作都命中时，优先显示 `FULL OUT` 或 `DROP LOW`。
2. 节奏命中但动作未完成时，主反馈显示节奏评价，旁边轻量提示“手臂伸直”或“再低一点”。
3. 节奏未命中时，显示 `Early`、`Late` 或 `Miss`；动作结果仍可记录，但不覆盖主节奏反馈。
4. 姿态置信度不足时，显示机位提示，不显示动作错误。

系统在同一时刻不报告多个动作错误。连续失误时应控制负面提示频率，避免反馈变成训话。

## 战绩卡

挑战结束后展示：

- 总评级。
- 总分。
- 节奏准确率。
- 动作完成率。
- 最高 Combo。
- 打开命中数。
- 蹲低命中数。
- 再来一局。

首版不展示最佳八拍、最弱八拍或弱段循环，因为系统只识别强拍，没有可靠的乐句和八拍结构。

## 技术方案

### 总体架构

首版采用纯浏览器、本地优先、模块可替换的 Web 架构：

- Vite、React 和 TypeScript 负责页面、流程和状态管理。
- Web Audio API 负责从本地视频解码音轨。
- 轻量 JavaScript 拍点分析器生成 BPM 和拍点网格，自研显著度筛选负责保留突出强拍。
- MediaPipe Tasks Vision Pose Landmarker 在设备本地输出单人姿态关键点和置信度。
- 纯 TypeScript 领域模块负责校准、运动特征、判定、计分和重试复核。
- Web Worker 负责离线音频分析，避免阻塞界面。
- Canvas 2D 和 CSS 负责骨架、实时反馈和轻量特效，不引入大型游戏引擎。
- Vitest、Testing Library 和 Playwright 负责自动化验证。

### 模块边界

- `beat-analysis`：音频 PCM 转换为候选拍点和显著度。
- `chart`：拍点启用、删除和 `rhythm`、`open`、`squat` 标记。
- `pose`：摄像头生命周期、MediaPipe 适配和标准化关键点。
- `calibration`：自动采集身体比例、动作基准和机位签名。
- `motion`：计算关节角度、髋部下降和整体运动速度。
- `judging`：输出节奏与动作状态结果，不依赖界面。
- `scoring`：计算分数、Combo、能量和战绩。
- `session`：管理上传、编辑、校准、挑战、结果和重试状态机。
- `ui`：展示流程、引导和反馈，不自行计算领域判定。

外部算法通过 `BeatAnalyzer` 和 `PoseProvider` 接口接入，使强拍算法或姿态模型可以替换而不改变产品规则。

### 强拍分析

1. Web Audio 解码视频音轨并转为单声道 PCM。
2. 首版拍点适配器生成 BPM 和候选拍点。
3. 系统计算候选拍点附近的短时能量变化或 onset 强度。
4. 系统过滤过弱、过密和疑似半拍或双倍 BPM 的候选点。
5. 用户通过试听、删除和动作标记确认最终谱面。

首版使用体积小、MIT 许可的 `music-tempo` 作为拍点适配器，但领域代码不直接依赖该库。`Essentia.js` 因 WebAssembly 体积、API 演进和许可要求不作为首版依赖，保留为未来可替换方案。

### 姿态识别与性能策略

- 使用 MediaPipe Pose Landmarker 单人模式。
- 桌面设备优先使用 Full 模型；推理性能不足时降级为 Lite。
- 姿态采样目标为约 20 FPS，界面渲染与姿态推理解耦。
- 首个技术验证阶段测量主线程推理耗时；出现明显卡顿时再将姿态推理迁移到 Worker，避免为未出现的性能问题预先增加复杂度。
- 降帧时优先降低识别频率或视觉特效，不改变媒体时钟和判定窗口。

### 数据与隐私

- 本地视频通过浏览器临时对象地址播放，不上传服务器。
- 摄像头帧、姿态关键点、四肢数据和校准结果不上传。
- 视频、谱面和校准数据默认只存在于当前浏览器会话中，刷新后可以消失。
- 首版不需要账号、数据库、云同步或应用后端。
- 公开部署使用 HTTPS 静态托管，自托管并缓存 MediaPipe 模型和 WebAssembly 资源。
- 首版优先支持桌面 Chrome 和 Edge；其他浏览器通过能力检测决定是否允许进入挑战。

## 测试与验证

### 自动化测试

- 肘部夹角、任意单臂伸直和单侧遮挡。
- 静态保持直臂连续满足多个“打开”动作状态。
- 节奏判定与动作状态判定相互独立。
- 髋部下降比例与下蹲命中。
- 关键点不可见时返回不可判定，而不是失败。
- 不同画面距离下，相同身体动作得到相近结果。
- 完整校准和 2 秒重试复核。
- 时间窗口、动作落点唯一匹配、Combo 和分数。
- 双倍 BPM、静音开头、弱强拍和默认密度过滤。

### 姿态序列测试

保存不含原始影像的姿态关键点序列作为确定性测试夹具，覆盖直臂、弯臂、单侧遮挡、快速落点、连续流动、站立、下蹲和不同镜头距离。

### 真人设备验证

验证不同身高、四肢比例、镜头距离、720p/1080p 摄像头、明暗光线、集成显卡与独显设备。首版重点验证 Chrome 和 Edge 的摄像头权限、媒体同步、识别性能和资源清理。

## MVP 范围

### 包含

- 15–60 秒本地视频上传。
- 浏览器端音乐强拍自动识别和显著度筛选。
- 强拍试听、预览、标记与删除。
- 只卡节奏、打开和蹲低三种有效卡点状态。
- 无需用户输入数据的自动身体与机位校准。
- 四肢比例、个人手臂伸直角度和条件式下蹲深度采集。
- 再来一局前约 2 秒的机位复核。
- 设备延迟补偿和捕获时刻时间戳。
- 摄像头人体姿态检测。
- 实时节奏和动作反馈。
- Combo、能量、Fever 和强视觉反馈。
- 战绩卡与一键重新挑战。
- 无需登录、无需后端的公开 HTTPS Web 应用。

### 不包含

- 舞种识别或舞种限制。
- 自动识别原视频动作或动作语义。
- 原舞还原度评分或逐帧姿势相似度。
- 左右手臂方向标注。
- 定住、转身、律动、身体分离、手型、脚部细节或表情判定。
- 自动识别八拍、乐句、最佳段落或最弱段落。
- 弱段循环练习。
- 录屏和视频导出。
- 用肢体手势控制倍速、播放、开始或停止。
- 复杂谱面编辑。
- 账号、云端视频库、公共分享、排行榜、多人模式或教学市场。
- 专业逐帧动作纠错。
- 成功门槛、观察信号、用户任务或数据目标。

## 关键产品与技术风险

### 快速到位的含义可能不直观

首次挑战前用简短动画解释：系统判断的是动作在强拍附近是否形成清晰落点，不判断是否与视频动作一致。

### 连续流动动作可能没有明确落点

产品不限制舞种，但应说明它更适合卡点强、动作幅度清晰的视频。若视频缺乏可用强拍，系统应如实提示，而不是生成密集或不可靠的卡点。

### 自动强拍可能出现半拍、双倍或过密结果

拍点分析后必须进行显著度和密度筛选，并提供即时试听和删除。强拍算法封装在接口后面，以便后续替换。

### 摄像头误判会破坏爽感

判定阈值偏向宽容。动作命中带来额外奖励，动作漏判不打断节奏 Combo；识别置信度不足时不判用户失败。

### 浏览器端推理可能影响媒体流畅度

界面渲染、媒体时钟和姿态采样相互解耦。首个技术验证阶段先测量 Full/Lite 模型的实际帧耗时，再决定是否迁移姿态推理到 Worker。

## 实施顺序

1. 验证真实摄像头骨架、肘部角度、髋部下降和整体动作落点。
2. 完成本地视频上传、音轨解码、强拍生成和显著度筛选。
3. 完成轻量谱面编辑。
4. 完成自动完整校准和重试机位复核。
5. 完成纯判定、计分和确定性姿态序列测试。
6. 串联完整挑战流程。
7. 添加 Combo、能量、反馈、特效和战绩卡。
8. 完成性能降级、错误恢复和浏览器能力检测。
9. 完成自动化测试与真人设备验证。
10. 通过 HTTPS 静态托管公开上线。
