# FullyDancy 骨架缓存、挑战教学与跳过流程设计

## 目标

优化当前原型的检验效率和挑战启动体验：复用分析阶段已经生成的示范骨架缓存，避免挑战页重复提取；进入挑战时先展示简洁的玩法与手势说明；为挑战前的每个页面提供统一的右下角“跳过”入口。

## 范围

本次改动覆盖首页、关卡选择、分析、校准和挑战五个现有页面，以及 `App` 管理的原型会话状态。

包含：

- 分析页把示范骨架缓存与确认后的卡点一并交给 `App`。
- 挑战页优先消费共享缓存，仅在缓存为空时执行一次兜底提取。
- 挑战页在申请摄像头和播放媒体前显示教学卡片。
- 首页、关卡选择、分析和校准页显示统一的右下角“跳过”按钮。
- 挑战正式画面移除与动作执行无关的信息。

不包含：

- IndexedDB 或其他跨刷新持久化。
- 多关卡缓存淘汰策略。
- 账号、云同步或上传骨架数据。
- 最终挑战页之后的新结果页面。

## 会话状态与数据流

`App` 继续作为页面状态机，同时持有：

- `chart: BeatPoint[]`
- `demoPoseCache: DemoPoseCache`

分析页的确认接口调整为一次返回 `chart` 和当前 `poseCache`。当用户正常完成分析时，`App` 保存两者并进入校准。挑战页通过 props 接收缓存，不再默认启动 `extractDemoPoseCache`。

如果用户跳过分析，`App` 使用内置关卡的默认卡点，并将骨架缓存设为空。挑战页收到空缓存时允许执行一次兜底提取，从而保证跳过流程仍可展示示范骨架。兜底提取结果只保存在当前挑战组件；本次不增加反向写回接口。

缓存仅存在于当前 React 会话，刷新页面后释放。摄像头画面与姿态数据仍不上传。

## 跳过流程

新增复用组件 `SkipAction`，固定在页面右下角的安全区域，使用一致的文字、焦点态和主题色。

页面行为：

1. 首页：进入关卡选择。
2. 关卡选择：选中当前内置关卡并进入分析。
3. 分析：使用内置默认卡点进入校准；若当前已经存在有效分析结果，则保留当前结果与已生成缓存。
4. 校准：直接进入挑战，不生成虚假的身体测量数据。
5. 挑战：最终层级，不显示跳过。

跳过是原型检验捷径，不改变主要按钮或正常用户流程。每个页面只出现一个“跳过”入口。

## 挑战教学卡片

挑战页首次渲染时显示模态教学卡片。卡片出现期间：

- 不申请摄像头权限。
- 不创建用户姿态识别循环。
- 不播放舞蹈视频或音乐。
- 背景挑战画面保持静止。

卡片只展示以下内容：

- 跟随绿色骨架完成动作。
- 单手张开保持 0.6 秒：播放或暂停。
- 双手举过头顶保持 1 秒：重新开始。
- 主按钮“开始舞蹈”。

点击“开始舞蹈”后关闭卡片，并在同一次用户操作链中申请摄像头权限、启动姿态识别和播放媒体。摄像头失败时保留可重试入口。

教学卡片每次进入挑战页显示一次；本次不跨会话记忆“已读”。

## 挑战画面信息层级

正式挑战画面保留：

- 全屏摄像头。
- 全高示范骨架。
- 摄像头或手势识别的必要状态。
- 播放、暂停和重新开始的备用按钮。
- 返回按钮。

移除：

- 页面标题。
- 英文模式文案。
- 卡点数量。
- 示范骨架提取帧数。
- 步骤编号和其他非动作信息。

文字继续直接悬浮在画面上，使用主题色，不增加文字底色。

## 组件与接口

- `App`
  - 新增 `demoPoseCache` 会话状态。
  - 负责正常确认和跳过流程的页面跳转。
- `AnalysisScreen`
  - `onConfirm` 返回 `{ chart, poseCache }`。
  - 新增 `onSkip`。
- `HomeScreen`
  - 新增 `onSkip`，行为与进入下一层一致。
- `LevelSelectScreen`
  - 新增 `onSkip`，行为与选择当前内置关卡一致。
- `CalibrationScreen`
  - 新增 `onSkip`，直接进入挑战。
- `ChallengeScreen`
  - 新增 `initialPoseCache`。
  - 新增教学卡片状态。
  - 仅在 `initialPoseCache` 为空时执行兜底提取。
- `SkipAction`
  - 接收 `onSkip`，渲染统一右下角按钮。

## 错误处理

- 分析阶段骨架提取失败时仍可确认卡点，缓存为空。
- 挑战兜底提取失败时不阻塞摄像头和音乐；画面只提示示范骨架暂不可用。
- 摄像头权限拒绝或设备占用时，显示简短错误和重试按钮，不重新显示整张教学卡片。
- 跳过分析时若内置默认卡点为空，使用当前关卡时长生成一个最小节奏点，避免流程断裂。

## 测试

- `App` 流程测试验证分析缓存被保存并传入挑战页。
- 分析页测试验证确认回调同时包含卡点和缓存。
- 挑战页测试验证有缓存时不调用提取器，空缓存时只调用一次。
- 挑战页测试验证教学卡片关闭前不申请摄像头、不播放媒体。
- 挑战页测试验证点击“开始舞蹈”后启动现有权限与媒体流程。
- 各页面测试验证右下角跳过按钮存在并触发正确的下一层动作。
- 全量 Vitest 和生产构建作为回归门槛。

## 验收标准

- 正常分析后进入挑战，示范骨架无需再次加载。
- 挑战开始前能清楚看到玩法和两个手势说明。
- 教学卡片之外不显示标题、卡点数量或缓存帧数等无关信息。
- 首页到校准页均可通过右下角“跳过”进入下一层。
- 挑过分析和校准后仍能进入可操作的挑战页。
- 正常流程、播放控制、手势控制和摄像头资源释放保持可用。
