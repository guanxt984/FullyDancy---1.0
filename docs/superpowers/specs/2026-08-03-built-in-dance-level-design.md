# FullyDancy MVP 内置单关卡设计

**日期：** 2026-08-03  
**状态：** 已确认  
**适用范围：** FullyDancy MVP

## 决策

MVP 取消用户上传视频。应用只提供一个内置舞蹈视频关卡，使用用户提供并授权公开分发的 `8月3日.mp4`。

本设计覆盖原产品蓝图和实施计划中关于“用户上传本地视频”“15–60 秒上传限制”“上传文件对象地址生命周期”的要求。其他核心产品规则保持不变。

## 目标

- 用户打开网站即可看到唯一的舞蹈关卡，无需准备或上传素材。
- 系统仍从该视频自动分析音乐强拍。
- 谱面不预设：用户在挑战前确认强拍，并为少量拍点标记 `open` 或 `squat`。
- 保持浏览器本地姿态识别、自动身体校准、节奏与动作独立判定。
- 实现以功能可用和代码轻量为优先，不为边缘格式兼容引入复杂解析。

## 媒体资源

- 源文件：`C:/Users/GXT/Videos/8月3日.mp4`。
- 发布位置：`public/levels/level-1.mp4`。
- 当前媒体信息：约 13 秒、11.5 MiB、1522×1080、30 FPS。
- 视频随静态站点同源公开分发，可被浏览器缓存和下载。
- 关卡配置只保存稳定 ID、标题和静态视频 URL；MVP 不建立通用关卡管理系统。

## 用户流程

1. 页面加载唯一关卡的视频预览。
2. 用户点击“分析卡点”。
3. 系统读取内置视频音轨并自动生成强拍候选。
4. 用户确认、启停强拍，并为少量拍点标记 `open` 或 `squat`。
5. 用户完成自动身体与机位校准。
6. 用户倒计时后进入挑战，完成后查看成绩。
7. “再来一局”继续使用同一视频和已确认谱面，并先执行约 2 秒机位复核。

## 删除与保留

删除：

- 上传文件控件和 `UploadStep`。
- `video/*` 上传校验和 15–60 秒限制。
- 用户视频的 `createObjectURL`、替换和释放流程。
- 上传相关端到端场景和提示文案。

保留并简化：

- 音轨解码与单声道 PCM 生成能力，输入改为内置静态视频。
- 自动强拍分析、显著度筛选和谱面确认。
- 摄像头、姿态、校准、动作判定、计分和重试流程。
- 所有摄像头帧、姿态关键点和校准数据仅在本地处理。

## 页面与状态

- 初始页只展示关卡预览、简短玩法说明和“分析卡点”按钮。
- 不增加关卡列表、搜索、账号或后台配置。
- 媒体加载或音轨解码失败时显示“关卡加载失败，请重试”。
- 不实现复杂的容器解析、转码或多格式兜底；首发以目标桌面 Chrome/Edge 能播放该内置 MP4 为准。

## 技术边界

- 使用 `public/levels/level-1.mp4` 的同源 URL 播放。
- 使用一个静态 `BuiltInLevel` 配置作为视频和后续流程的入口。
- 音轨分析可以通过同源 `fetch` 读取视频字节，再复用浏览器音频解码能力。
- 不创建对象 URL，不上传视频，不请求第三方媒体服务。
- 不提前建设多关卡抽象；未来增加第二关时再扩展配置结构。

## 测试范围

- 初始页面不存在文件上传控件。
- 页面显示内置关卡视频和“分析卡点”操作。
- 点击后，内置媒体会进入音轨解码和强拍分析流程。
- 加载或解码失败时显示统一重试错误。
- 原摄像头与姿态技术验证测试继续通过。

不要求为 MVP 编写复杂格式、跨浏览器媒体容器或静态文件服务器本身的测试。

## 验收标准

- 用户无需选择文件即可开始唯一关卡。
- 内置视频能在目标桌面 Chrome/Edge 播放。
- 系统能从内置视频生成可确认的强拍候选。
- 用户可以继续标记 `open` / `squat`，并进入后续校准与挑战流程。
- 页面和网络请求中不存在用户上传入口或用户媒体上传行为。
